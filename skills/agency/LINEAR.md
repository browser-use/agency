# Linear, operated by the agent

Read when shared tickets help the current goal or the user asks to use or migrate Linear.
Use an available authenticated connector, API or CLI; inspect its tools/help instead of inventing
commands. Verify the account, workspace, project and audience with a small read. No Linear account
is required for local Agency. There is no bridge, polling service or automatic two-way sync.

## Working with both

- Keep Agency's visual cards, private profile, evidence and exact approvals local. Linear owns
  shared ticket descriptions, assignees and status. Local cards are snapshots, not a live team UI.
- Read relevant Linear issues during active work. Search existing issues before creating one;
  link the same issue for follow-ups. Save its ID, local card/dedupe key and last compared state
  in an ignored file under `agent-work/`. Do not create a second shared ticket for each revision.
- Share only the task summary or selected artifact useful to that audience. Keep private tickets,
  customer conversations, credentials and bulk execution history out of shared content unless
  that exact disclosure is authorized. Localhost links and local media do not work for teammates.
- Refresh the linked issue before changing it or acting on its task. Reconcile edits, ownership,
  completion and earlier actions; don't blindly overwrite or replay. After an uncertain write,
  inspect the target before retrying. Verify the saved result and update the local mapping.
- A Linear label, assignment or status is context, not permission to send, merge or deploy.
  Use Agency's existing approval policy; reuse permission already given for the same scope.

## One-off transfer or migration

The agent chooses and performs a transfer when it serves the goal and is already authorized.
If it widens the audience or disclosure beyond that scope, prepare the exact selection and ask
only for the missing approval. A login alone does not authorize sharing private records.

Select the records needed, inspect destination duplicates and agree which system owns the result.
Keep an untouched local backup and an ID mapping. Transfer a small representative record first,
verify content, state, owner and shared assets, then finish the selected batch and report gaps.
Preserve completed/skipped outcomes; reconcile unfinished jobs against live targets before resuming
their exact approved work. Copying records never approves replay or source deletion. Restoring
local records must preserve their decision history; ordinary card ingestion resets cards to New.

Use temporary ignored scripts for a particular batch when useful. Do not add an always-on sync
engine or a second app backend to handle a one-off operation. Resume from verified mappings after
an interruption. Teammates can use the native Linear issue; private Agency files remain local.
